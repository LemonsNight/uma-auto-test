## 二、阶段 2：虚拟圆点（未发送点击）

结果：**15/15 通过**

- 窗口标志实测：`WS_EX_TRANSPARENT`、`WS_EX_NOACTIVATE`、`WS_EX_LAYERED`、`WS_EX_TOOLWINDOW`、`WS_EX_TOPMOST` 全部为 ON。
- 圆点移动到主屏、副屏、负 Y 坐标（`(3000,-40)`）时，实测中心与指定坐标完全一致。
- `WindowFromPoint` 在圆点位置命中下层窗口（`FolderView`），未命中 Overlay，鼠标穿透成立。
- Overlay 显示前后前台窗口不变，不抢焦点。
- 连续 12 次移动圆点，真实光标位置不变。
- 显示/隐藏正常。
- 重要实测：Qt `move(3000,100)` 落在 `(3220,194)`，混合 DPI 下错误；
  改用 Win32 `SetWindowPos` + 二次校验后全部正确。跨 DPI 边界时 Qt 会异步改变物理尺寸，
  需要多次收敛（已实现 6 次迭代）。

截图：`screenshots/phase2_dot_primary.png`、`phase2_dot_secondary.png`（均已目视确认红点存在）。

## 三、阶段 3/4：输入模块、状态机、全局热键

结果：**15/15 通过**

- `LPARAM` 编解码（含负坐标）正确；越界坐标拒绝发送。
- 源码静态检查：无 `SetCursorPos(` / `SendInput(` / `mouse_event(` / `pyautogui(` 调用。
- `WindowFromPoint` 正确解析到测试窗口；`RealChildWindowFromPoint` 用 ctypes 实现（pywin32 无此函数）。
- PostMessage 三条消息顺序与 wParam 正确：`WM_MOUSEMOVE(0)`、`WM_LBUTTONDOWN(MK_LBUTTON)`、`WM_LBUTTONUP(0)`；全部入队成功。
- 入队结果与"实际点击验证"字段严格分离，验证字段始终为"未验证"。
- 拒绝向 `Progman` 系统桌面窗口发送点击。
- 状态机：启动/暂停拒绝点击/恢复/紧急停止拒绝点击与移动/复位，全部符合预期。
- 全局热键 `Ctrl+Alt+Shift+K` 注册成功；投递 `WM_HOTKEY` 后立即触发紧急停止。
- 主程序装配冒烟测试 6/6 通过；修复了 `QScrollBar.moveToBottom()` 在 PySide6 中不存在的缺陷。

### 关于"真实鼠标未被移动"的实测结论

- 阶段 2 连续 12 次移动圆点：光标 `(1543,794) -> (1543,794)`，不变。
- 隔离验证 `tests/test_mouse_isolation.py`：
  - 对照组（无任何动作 0.6s）：`(1136,423) -> (1136,423)`，不变；
  - 实验组（25 次移动圆点 + 点击）：`(1136,423) -> (1136,423)`，不变；
  - 源码静态检查无禁用 API。
- **曾出现的干扰**：阶段 5 的早期一次运行中，浏览器场景采样显示光标
  `(1102,459) -> (1129,569)`；该共享桌面存在外部鼠标活动，该次差异不作为程序行为证据。
- **最终回归结果**：全部测试重跑后，阶段 5 浏览器场景采样为
  `(1419,0) -> (1419,0)`，一致；隔离实验同样一致。
  结论：程序不移动真实鼠标，通过验收。

## 六、未验证 / 失败项目

- **无遗留失败项**：阶段 5 早期一次运行的"光标位置"采样曾受外部鼠标活动干扰；
  最终回归与独立隔离实验均通过，该项已关闭。
- **未验证**：不同 Qt 版本与不同 Windows 版本下的窗口标志实际行为。
  只在 PySide6 6.12.0 + Windows 11 build 26200 上实测；代码中已做运行时校验与二次收敛，
  但不声称其它组合一定成立。
- **未验证**：UIPI / 不同权限级别 / 受保护系统窗口的实际限制表现。
  代码会报告 `GetLastError` 与限制说明，不尝试绕过。
- **未验证**：窗口被**完全**遮挡时的记事本点击。坐标式设计只能命中当前位于该屏幕坐标的窗口，
  完全遮挡时该坐标属于遮挡窗口，不会点击到记事本。
- **未验证**：业务程序（赛马娘）中的点击效果。本阶段明确不开发业务自动化；
  PostMessage 入队成功不等于游戏处理了点击。
- **未验证**：多显示器热插拔 / 分辨率动态变化后的坐标重新校准。
